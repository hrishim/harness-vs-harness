harness-vs-harness

We gave AI agent programs the same 15 everyday tasks, three times each, and measured how correct they were and what they cost to run.

What this is

A harness is the program wrapped around an AI model that lets it read files, run commands and work through a task on its own. Different harnesses can get quite different results from the same model, so we hold the model fixed and change only the harness.

The 15 tasks are things a person does on a laptop: filling in an expense claim, importing bank statements into accounting software, sorting an inbox, planning a trip, fixing a bug. Each task is given as one plain request with no follow-up questions. The answers are scored by rules and automated checks, never by another AI. Score is the percentage correct; real tokens is how much work the model did on a run (the new text it read plus everything it wrote, including its thinking).

How to read a score

A score like 99% does not mean the work was safe to use. Many of these tasks are all-or-nothing in real life: if an accounting file is edited wrongly, or the total on a claim is wrong, you cannot rely on the result, however close it was.

We still give partial credit on purpose, because it shows progress. A newer version of a harness may still fail a task but fail it more narrowly, and the partial score shows it is heading in the right direction. So read the average score as how close the work was, and the number of fully correct runs as how often you could rely on it.

What are "real tokens"?

A token is a small piece of text, roughly three quarters of a word. Each time the model takes a step, the harness sends it the whole conversation so far, so the same text is read again and again. The server remembers text it has already processed and reuses it (a cache), which costs almost no work.

Real tokens count only the work that was not reused: the new text the model had to read, plus everything it wrote, including its thinking. Counting the reused text as well would bury the real differences, because long conversations re-read the same text many times. Real tokens follow the actual effort (and the waiting time) much more closely.

Example: one Pi run (T10 Warranty tracker, round 2) took 24 steps. Over those steps the model was sent 283K tokens in total, but 190K of them were reused from the cache. So it had to read 93K new tokens and it wrote 10K. Real tokens = 93K + 10K = 104K.

See exactly what each task asked on the Tests page, and how everything was run (model recipe, harness versions) on the Setup page.

The results

The model can think before it answers, and how hard it thinks depends on a setting called reasoning effort. Every harness was run at two levels, medium and xhigh (the highest). Higher effort changes both cost and results, so compare harnesses only within the same effort level.
